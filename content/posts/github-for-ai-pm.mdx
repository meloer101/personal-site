0. 请你首先创建一个github账号，然后进入profile，也就是你的个人github主页
1. 左上角有几个标签，只需要知道其中Overview是你的个人展示的主页（也就是面试官对你的第一印象），repositories是你的所有的代码仓库，stars是放置 ± 你所有收藏的项目的地方
2. 对于你的GitHub来说，所要关注的重点就是Overview和repositories，我们先来说Overview：

<img src="/blog/github-guide/overview.png" alt="GitHub 个人主页左栏：头像、名字、简介、关注数、所在地、邮箱和社交链接" width="344" height="661" />

左边的邮箱、社交账号和沟通渠道需要无比清晰，虽然大概率没啥用但是以防万一，其中个人简介其实没有想象中那么严肃，你可以一两句话概括自己，或者写两句玩笑话，因为你真正的个人展示是在右边的README.md中完成的

这一部分的下面你会看到很多人有许多徽章，可有可无，如果你觉得想要好看点的话直接问你的chatGPT、claude让它给你建个仓库然后多merge几个PR自然就有了。

![GitHub 个人主页右侧的 username/README.md 名片模块](/blog/github-guide/readme.png)

如果你在github上面多逛逛并看看别的user的主页你能看到几乎在右边都有一个上面写着username/README.md的类似于名片的模块，但是其实这是一个仓库中的内容。

```markdown
README实际上是什么
它本质上就是一个普通的Markdown文件（.md格式），最初的用途是放进任何一个项目仓库里，用来说明"这个项目是做什么的、怎么用"。但GitHub在2020年上线了一个官方功能：

Profile README：如果你新建一个仓库，仓库名和你的GitHub用户名完全一致（比如用户名是mirayatech，仓库名也叫mirayatech），并且这个仓库是Public的，GitHub就会自动把仓库里的README.md内容渲染显示在你的个人主页最顶部，看起来就像一张会格式化的动态名片。所以严格说，它不是"主页功能"，而是"一个特殊命名的仓库+一个被自动读取的文件"。

怎么创建
1. 点击GitHub右上角的"+"号 → New repository
2. Repository name 里输入和你用户名完全相同的名字——这一步是关键，名字对上了GitHub才会识别成profile专属仓库（如果输对了，页面会弹出提示"You found a secret unlockable feature!"，这也是很多人第一次发现这个功能的契机）
3. 设置为Public
4. 勾选"Add a README file"
5. 创建后打开仓库，编辑README.md，用Markdown语法写内容——常见的有自我介绍、技能栈（Tools & Tech）、正在做的项目、联系方式、甚至个人爱好这种"关于我"的碎片信息（就像截图里Miraya的主页那样）
6. 保存后回到自己的主页，就能看到这份内容自动出现在头像旁边了
这样和你上一段"看起来像名片，其实是仓库内容"的观察正好接上，逻辑是：先破除误解（这不是页面功能）→ 再揭示真相（是文件+命名规则）→ 最后给出可操作步骤。
```

如果上面的内容有些难懂的话，还是请出你的claude code和codex，（但是其实我还是希望大家能够弄懂，至少要自己会创建github仓库吧hhh）告诉它请你帮我创建我的个人的github READEME，你要做的最重要的事情只有一个：

***选择你的github主页的README中你想要展示什么***

我的个人建议：

- 学历（当然如果你觉得实在没有竞争力的也当然不必，github上从来没有人会真的去关注学历，但是我们现在是在求职的话另说，毕竟面试的时候面试官还是会扫一眼的）
- 你的自我定位：不仅是AI PM这个岗位名词，而是你对于AI PM的理解（可以是格言式的发言），以及你对于自己这个“AIPM“的定位，也就是你准备在这个岗位上去做些什么
- 你希望展示的好项目，附上链接
- 你会的技术栈和工具（告诉AI你想用图标的形式，它会帮你完成的）
- 你的github star和contribution数（太少的话你可以斟酌一下，虽然本人加起来就5个也加上去了）
- 想要好看点的话可以放上点喜欢的横幅（动漫之类的都行，既养眼又展示点个性是ok的）

最后如果你实在不想花费太多时间的话去小红书上直接搜github主页然后把你喜欢的喂给AI让它帮你完成即可。

再往下看你便会看到user向外展示的仓库：

![GitHub 个人主页上的 Pinned 仓库区域](/blog/github-guide/pinned.png)

那么这个时候就有一个有趣的问题，那就是repositories里本来就有user所有的仓库，为什么这里还有呢，所以说这也体现出这Pinned的仓库的性质，它属于你主动向外展示，并且是认为这些是能够体现你的个人能力和关注点的仓库。

那么我们该如何选择呢？其实也很简单，第一个思路：选你被收藏（star）最多的仓库；但是其实大部分人的仓库的star也不会有太多，所以我们最好也换换思路，就从我们要应聘的岗位：AI PM入手

很多人一看AI PM，就立马pin上所有的agent项目，什么harness、多agent、mcp、skills全上来了，其实这反倒还让别人以为你是来应聘agent开发岗的，其实完全有更好的思路：**一个不要求特别全面，但是已经被你完全吃透的agent项目能够体现你的专业竞争力；一个完美嵌入你的工作流，帮助你更好完成产品经理工作的skills仓库能够体现你对于产品经理工作内容和流程的理解；一个你自己vibacoding的小工具能够展示你的动手能力和行动力，比如：展示你的剩余的codex和cc额度的小工具，一个小的项目管理工具；最后pin一个自己fork，提过pr、issue，反正能放到你的主页来的高star项目能够体现出你的社区活跃度和积极性**，这不比你哼哧哼哧放几个大同小异的toy agent版苍穹外卖强的多。
